## 현상

키보드입력으로 변경시 키보드가 입력창을 가리고있어서 어떤 내용을 입력하는지 알수가없음. 이것은 다른 메뉴에서도 모두 동일하게 동작하는것으로 예상되어, 입력창이 존재하는 곳 모두 수정필요

## 기대하는 모습

(위 현상 해결 — 입력창이 키보드에 가려지지 않도록 앱 내 입력창 전체 공통 수정)

## 근거

## 분류 메모 (착수 때 Leader)

- 재확인: 부분 완화만 됐고 현상은 유효할 가능성 높음(실기기 재현 필요). 이미 있는 것: 루트 `interactiveWidget: 'resizes-content'`(`layout.tsx`), Manifest `adjustResize`, 채팅방·회화방(텍스트 모드)·오늘의 회화 5단계에만 `useKeyboardInset`+`--kb-inset`(`ChatRoom`·`TalkRoom`·`LessonScreen`). Manifest 주석대로 targetSdk 35 edge-to-edge 에선 adjustResize 만으로 창이 안 줄 수 있음.
- 빠진 곳: 바텀시트(`Sheet.tsx` — `WordAddSheet`·`NewChatSheet`·`AcceptCorrectionSheet`·`ChatMenuSheet` 등 입력 시트)와 `LessonPasteScreen`·`StageApply`·`StageUnderstand` 메모 입력·설정 입력(`VoiceSettings`·`LearningSettings`)에는 키보드 보정이 없다. 회화방 텍스트 모드 자체도 사용자가 재현한 화면이라 앱(WebView)에서 왜 안 먹는지 원인 확인이 필요.
- 영향 파일: `useKeyboardInset.ts`(공통화), `Sheet.tsx`, 위 입력 화면들, 필요 시 앱 셸/Manifest·`capacitor.config.ts`(네이티브면 APK 재빌드). 규모 M. Leader 의견: 공통 해법(앱 전역 visualViewport/Keyboard 처리 또는 네이티브 windowInsets 처리)으로 한 번에 — 화면 개별 task 에 흩뜨리지 않고 '공통' task 로. 착수 시 실기기(웹 Chrome·앱 WebView 각각) 재현이 첫 단계.

## 착수 결정 (사용자 답변, 2026-09-30)

- 입력창이 있는 모든 화면 공통 해법. 웹 우선, 네이티브가 꼭 필요할 때만 APK 재빌드(고지).
- 우선순위·순서는 사용자가 지정하지 않아 **Leader 권고 순서**(P1→P2→P3)를 잠정 채택했다. 사용자가 바꾸면 이 값을 고친다.
