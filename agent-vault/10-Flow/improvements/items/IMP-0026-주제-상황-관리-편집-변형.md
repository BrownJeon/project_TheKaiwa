## 현상

(사용자 원문, 2026-10-07)
> 1번에 대하여 다양한 주제와 상황에 대하여 시나리오를 생성할 수 있도록 설정메뉴쪽에 시나리오 편집기능이 있었으면 좋겠어. 물론 AI가 기본적인 주제나 상황을 생성해주는게 기본적으로는 좋지만, 추후에 다양한 상황에 대하여 회화연습을 하기 위해서는 시나리오를 바꿔가며 상황을 연출해주는 기능이 필요해.

(Leader 확인 사실 — 코드 읽기, 2026-10-07)
- 상황(시나리오) 만들기(AI 초안 → 고쳐 저장)·고치기·지우기는 회화 탭 '시나리오'에 이미 있다(API `scenarios` GET/POST/PATCH/DELETE·`drafts`). 편집 칸: 제목·일본어 제목·장소·수준·역할·목표·대화 순서(2~8)·성공 조건(1~3)·표현(2~12)·첫마디·난이도. 상한: 내 상황 50개·하루 만들기 30개.
- **주제(장소)를 사용자가 만들거나 고치는 경로는 앱 코드에 없다**(`conversationTopic` 쓰기는 시드 스크립트뿐). 상황은 주제 1~3개에 붙는데 기본 주제가 5개(자기소개·카페 주문·길 묻기·주말 계획·여행 이야기)뿐이라 챌린지 주제 목록도 5개다.
- 기본 시드 상황 10개는 읽기 전용(`userId null`·`isSeed`)이고, 시드 로더(`prisma/seed-scenarios.ts`)를 다시 돌리면 시드 행의 `keyExpressions` 가 시드 JSON 값으로 되돌아간다.

## 기대하는 모습

사용자 결정(2026-10-07, 질문 5건에 대한 답 — 원문):
1. "사용자가 주제를 모두 주체적으로 생성하기는 어려우니 기본적으로는 **사용자가 주제만 입력해주면 AI가 초기로 상황에 대한 시나리오를 생성하고 사용자가 검토하여 수정하는 형태**로 진행하자"
2. 진입점: **설정 메뉴에 "내 상황·주제 관리" 항목**을 두고, 회화 탭의 편집 진입은 유지하며 두 진입점이 같은 화면을 쓴다(Leader 안에 대한 "그렇게 진행해줘").
3. "**변형 연출도 이번 범위안에 넣어줘.**"(같은 상황의 조건·성격·분기를 바꿔 연출 — 방식은 designer 가 선택지로 제시)
4. "**기본 시드로 편집가능하도록 해줘.** 사용자의 회화수준이 올라감에 따라서 기본 시드가 필요없어지는 상황이 오기때문에 기본 시드의 상황도 사용자와 마찬가지로 표현의 수준이 올라갈 것으로 예상 돼"
5. "**주제를 지우면 상황과 진행중인 챌린지는 제거하되, 이미 완료한 챌린지는 그대로 유지**해줘. 다만 삭제하는 주제에 대하여 **진행중인 챌린지가 있으면 삭제여부 alert처리시 진행중인 챌린지가 존재하는 문구를 추가해서 알려주도록** 해줘"

추가 결정(2026-10-07 ②, 원문):
6. "시드 편집에 대하여 **기본 시드 및 사용자가 변경한 시드의 경우 사용자별로 별도로 관리할 수 있도록 구조를 변경해줘.**"
7. "주제 생성에 대하여 **claude cli를 통해서 AI작업을 추가해줘**"
8. "완료된 챌린지 중에 삭제된 주제의 경우에 **별도 삭제표기는 안해줘도 될것같아.**"

Leader 가 채택한 기본값(사용자가 답하지 않은 항목 — 이의 있으면 데모에서 조정; developer 설계 조사 `dev-045-spec` 의 ②~⑧):
- ② 진행 중 챌린지 "제거" = **행 삭제**(사용자 원문 "제거"에 가까움, 자식 행 없음). 끝낸(완료) 챌린지는 유지. ※ `docs/design/challenge.md` §3-3:253 "진행 중 챌린지가 쓰는 주제는 삭제 409" 와 반대이므로 **정본 개정 필요(Leader)**.
- ③ 시드 주제·상황의 "삭제" = **그 사용자의 목록에서만 숨김**(되돌릴 수 있음, 다른 사용자 영향 없음).
- ④ 여러 주제에 걸린 상황은 **연결만 끊고**, 모든 주제가 사라진 상황만 보관(ARCHIVED).
- ⑤ 변형 연출: **A(변형 상황 초안 → 저장)** 먼저(DB 변경 0), B(시작 전 연출 옵션, `Chat.scenarioVariant Json?` 칸 필요)는 데모에서 사용자가 고르면 별도 DB 승인.
- ⑥ 시드 사본 주제의 "주제 표현 진행"은 0부터 다시 센다(조각 id 가 새로 생김).
- ⑦ 상한(조정 가능): 내 주제 ≤30 · 주제 저장 하루 10 · 초안 분당 6·하루 20.
- ⑧ 시드 사본을 만든 뒤에도 원본 주제에서 이미 진행 중인 챌린지는 계속 진행.
- DB 최소안(dev-045-spec): **새 표 `UserSeedOverride`**(`id`·`userId`(Cascade)·`kind`·`seedId`·`copyId?`·`createdAt`·`updatedAt`, `@@unique([userId,kind,seedId])`) — "시드도 사용자별로 따로 관리"(결정 6)에 대응. 다른 칸·표 추가 없음(변형 B 를 고르면 `Chat.scenarioVariant Json?` 추가).
