## 현상

오늘의 단어 카드의 [한글] 줄이 단어에 따라 「이 카드는 한글 표기가 없어요」로 나온다(사용자 스크린샷: 4/10 「温い」). 한글 줄은 DB 값이 아니라 서버 분석기가 표기를 읽은 발음으로 화면에서 만들고, **분석기 읽기가 저장된 읽기와 다르면 일부러 숨긴다**(task-026 승인 보호 규칙: 「서로 어긋난 발음을 보이지 않는다」). 「温い」는 저장 ぬるい vs 분석기 ぬくい.

운영 분석 API 로 기본 단어 7,757개 전수 점검(2026-10-15, 읽기 전용): 정상 7,468(96.3%) · 읽기 불일치로 숨김 286(3.7%, 전부 한자 포함) · 발음을 못 구해 숨김 3(何々 2·精々). N5 는 678 중 21.

## 근거

- 개념 검증(2026-10-15, 읽기 전용): 숨겨진 289개의 **저장 읽기(히라가나)를 같은 분석기에 넣으면 288개(99.7%)가 저장 읽기와 일치하고 한글 줄이 만들어진다**(예: 温い→누루이, 丈夫→죠-부, 黄色→키-로, 四→시, 毎年→마이넹). 남는 1개는 七(しち) — 저장 읽기만으로도 분석기가 발음을 못 구함 → 보호 규칙대로 계속 숨김.
- 새 장음·촉음 변환 규칙을 만들지 않고 **같은 분석기(같은 발음 규칙)** 를 한 번 더 쓰는 방식이라 기존 한글 표기와 표기법이 일치한다.
- 코드: `src/components/common/japanese/annotations.ts` `readingMatches`(:377)·`wordHangulState`(:387)·`useWordLayersList`(:405) — 한글 줄 소비처는 이 훅 하나를 공유한다(단어장 행·상세·오늘의 단어 덱·교정 제안 카드·평가·챌린지 생성).
- 숨기는 쪽 보호 규칙의 출처: [[task-026-improve-hangul-reading]].
- 저장 읽기 자체가 의심스러운 경우(예: 私=わたくし, 一月=ひとつき)가 불일치 안에 섞여 있다 — 이번 범위는 **표시**만이고 저장 읽기 검수는 별도(후보 C).
