## 현상

기본 단어 팩(초보자 N5 676 · 초급 N4 629 · 중급 N3 1,649 · 고급 N2 1,767 · 최상급 N1 3,034 = 7,755개, task-051)은 사용자가 「기본 단어 n개 한 번에 넣기」 버튼을 눌러야 내 단어장에 복사된다. 버튼은 빈 단어장 화면과 「단어 추가」 시트 아래쪽 작은 글자에만 있어 찾기 어렵다. 2026-10-14 조회 기준 실제 사용자 계정의 단어장은 678개(전부 기본 팩 출처, 초보자 N5 만 넣은 상태)이고 N4~N1 은 들어 있지 않다.

## 기대하는 모습

> 2. 기본 배포해놓은 단어 7755개의 단어는 처음부터 추가해놔야하고 사용자가 필요한 단어들을 추가하는 형태로 구현될 수있도록 해줘.

(사용자 요청, 2026-10-14)

## 근거

- 단어는 사용자별 복사본(`WordEntry`, `source=SEED`)이라 "처음부터 추가"는 ① 새 사용자는 가입(계정 생성) 때 ② 기존 사용자는 한 번 백필(공유 NAS DB 쓰기 — 사용자 승인 필요)로 넣는 두 경로가 필요하다.
- 사용자 계정 8개 중 실사용자는 구글 1개(678개), 나머지 7개는 QA용 빈 계정. QA 계정까지 채우면 QA 가 쓰는 빈 단어장 기대(시험·스모크)가 바뀐다 → 실사용자(비 test provider)만 대상으로 할지 데모·결정에서 정한다.
- 삭제한 기본 단어가 다시 들어오지 않게 하려면 「한 번만」 규칙이 필요(계정 생성 시 1회 + 백필 1회면 표지 컬럼 없이 가능).
- 연관 화면: 빈 단어장 CTA(`WordsEmpty`)·오늘의 단어 빈 카드(`TodayWordsCard`)·단어 추가 시트 아래 기본 단어 버튼(`WordAddSheet`)은 필요 없어진다.

## 구현 방식 변경 (2026-10-14, 사용자 추가 지시)

> 단어테이블에 기본 단어와 사용자단어 데이터를 분류하고 기본 단어는 모든 사용자가 기본적으로 보는 것으로 하고 읽기전용으로 사용하며 사용자가 추가한 단어에 대해서는 사용자가 입력한 값에 대해서 DB테이블에 적재하고 사용자만 관리하는 형태로 구현해줘

- 위 「근거」의 사용자별 복사·가입 때 넣기·기존 사용자 백필 방식은 **폐기**. 기본 단어는 공용 읽기 전용 행(소유 사용자 없음)으로 한 번만 두고 모든 사용자가 즉시 본다. 사용자별 학습 기록·보관은 `UserWordState` 에 따로. 설계는 [[task-068-improve-wordbook]] 「DB 구조」.
