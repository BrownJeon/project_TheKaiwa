## v1 요지
- 바뀌는 곳은 ③ 난이도 `fieldset` 맨 아래 **한 곳**: 고른 난이도가 **주제보다 2단계 이상 어려우면** 기존 `InfoBox`(제목 없음) 하나가 나타난다. 한 단계 이내·아래 방향(★)은 없다. 막지 않고 경고색·아이콘·`role="alert"` 없음.
- ★ 문구(C2): 「이 주제보다 많이 어려운 난이도라, 새 단어가 모자란 날은 주제 표현으로 채워요.」 — 서버 개선이 합격하든 실패하든 맞는 말(합격해도 평균 2장 안팎은 주제 표현), 카드가 쉬워지는 이유를 말한다. 단계 수·난이도 값이 없어 알약을 N2↔N1 로 바꿔도 다시 읽지 않고 조사 문제(§33-1a)도 없다.
- 기존 안내 줄(내 수준 기준)과 기준이 다르다 → 상자로 구분(질문 4 a). 스크린 리더는 늘 그려 두는 `aria-live="polite"` 감싸개 하나로 기존 줄 + 상자를 묶는다(`role="note"` 는 나타날 때 읽지 않아 쓰지 않음).
- DB·API·서버 변경 없음. 새 순수 함수 `wordsLevelNote(sel, topicLevel)` + 문구 상수 1개.

## 사용자에게 묻는 질문 (데모 맨 위 — ★ = 권고, Leader 확인 전 designer 안)
1. **표시 조건·문구** — A 직접(«적게 나올 수 있어요», 개선 합격 시 어긋남) · B A + 개선 뒤 측정으로 «보일 차이 목록»을 코드에 고정(조건이 승인 뒤로 미뤄짐) · C1 Leader 예시 「단어 난이도는 주제에 따라 달라질 수 있어요.」 · **★ C2** designer 다듬은 중립+이유 문구. 데모의 «사실 대조 표»가 개선 전/합격 두 가정에서 각 안이 맞는 말인지 보여 준다. A 의 개선 합격 시 대안 문구 = C2(또는 숨김).
2. **아래 방향(주제보다 2단계 이상 쉬움)** — **★ a 안 보임**(측정 없음 — 이번 서버 측정 계획에도 없음) · b 보임(아래 방향 문구) · c 서버 측정에 «주제 N2 × N4·N5» 추가(약 6회, 예산 승인) 후 결정.
3. **「오늘의 단어」 목표를 끈 경우** — a 숨김(카드가 71~83px 움직여 다시 누르면 아래 회화 카드를 잘못 누를 수 있음) · **★ b 차이 규칙 그대로**(브리핑 조건 그대로, 화면 안 움직임).
4. **모양·자리** — **★ a 난이도 묶음 맨 아래 상자(InfoBox 재사용)** · b 상자 없이 기존 안내 줄 다음 한 줄(기준이 섞임) · c 「오늘의 단어」 카드 바로 아래(난이도 고르는 자리에서 안 보여 놓칠 수 있음).

## Leader ★(브리핑)와 다르게 그린 곳
- **질문 1 ★ 를 C2 에 둠** — 브리핑은 A/B/C 와 C 예시(= C1)만 주고 ★ 를 정하지 않았다. 긴장 ②(개선 성공 시 «적게»가 틀림)를 문구 하나로 푸는 쪽을 designer 안으로 ★ 표시했다 → **Leader 가 게시 전 ★ 를 확인·수정해 주세요.** C2 의 약점(개선 실패 시 빈도를 낮춰 말함)은 질문 카드와 §35-8 에 적었다.
- **질문 3·4 를 더함** — 브리핑 질문은 아래 방향 하나였다. 질문 3 은 코드에서 «단어 목표를 끄면 새 단어를 안 만듦»을 확인해 생긴 경계, 질문 4 는 기존 안내 줄과 겹치는 자리 문제. 질문 총 4개(상한 5 안).
- **스크린 리더 = `aria-live="polite"`**(브리핑은 `role="note"` 또는 `aria-live` 중 택1) — 그리고 **기존 줄의 `aria-live` 를 감싸개로 옮기는** 구현 수준 조정을 권고했다(§33 의 보이는 모양·문구는 불변).
- **B 의 해석을 좁힘** — «측정 통과율이 낮은 경우에만»을 실시간 통과율이 아니라 «개선 뒤 측정으로 정한 고정 목록»으로만 그렸다(실시간이면 API 변경 = 범위 밖).
