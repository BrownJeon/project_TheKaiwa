## 3. 정본과 어긋난 곳 (Leader 문의 — 데모 개발 메모 2절에 13건)

1. #78 응답이 주별뿐 → `streak·longestStreak`·`days[]`·`skills[]` additive 필요.
2. #78 `errorTrend` 는 «스냅샷만» 원칙으로 불가 → 제외 권고.
3. §7-6 «수준 이력» 원천 없음(`Profile.level` 덮어쓰기만) → Q5.
4. 듣고 응답 축 생산 코드 0 → 별도 작업 필요 여부.
5. DAILY `observations.bySkill` 이 CORRECTION_ACCEPTED=SUCCESS 를 섞음 → §2-3 «채택만으로 올리지 않는다»와 충돌 → Q4.
6. schema 주석 «성장기록·분석은 StatsSnapshot 에서만» vs §7-6 분석 입력(LearnerErrorStat·RepetitionItem 등) — 문구 정리.
7. #74 [다시 분석]: «PROPOSED 있으면 새로 안 만듦»과 새 기록이 있을 때의 처리 규칙 없음(권고: 같은 hash → reused, 다르면 서버가 기존 PROPOSED→REJECTED 후 새 잡).
8. `StudyPlan` 에 입력 요약 없음 → `analysis.inputs`(숫자만) 저장 제안.
9. `evidence{metric,value}` 한국어 라벨은 코드 상수로.
10. #74 `weeks` 1~4 → 화면은 [2주][4주].
11. 잡 진행 단계 이벤트 없음 → 움직이는 띠 + 시간 안내.
12. 계획 항목 완료 표시는 계약에 없음.
13. 분절 주소 방식(`/plan/analysis`·`/plan/growth` vs `?view=`) 미정.
