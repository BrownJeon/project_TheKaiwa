# task-078 PE 진단 기록 — A12 `topicWords@v2` 두 단계 이상 차이에서 새 단어가 떨어지는 사유 (서버 코드 변경 없음)

> 지시: Leader 의 task-078 진단 단계(PE, 라이브 호출 15회까지). 하네스 `tests/prompts/topic-words-level-live.ts`(신규), 결과 JSON 은 스크래치패드 `pe-078-diag/live.json`(행별 원본 응답·항목별 상태)·`live.summary.json`. `src/**`·프롬프트·검사 코드는 건드리지 않았다. 모델 haiku(운영 A12 와 같은 경로), 주제 = 픽스처 N4 주제 `weekend-plan`(주말 계획), 목표 10장(요청 13), 제외 목록 = 그 주제 기본 표현 12개.

## 0. 먼저 읽을 것 (결론과 불편한 사실)

**한 줄 판정**: 두 단계 차이에서 새 단어가 떨어지는 사유는 **검사 ⑤ `JLPT_WINDOW` 하나뿐**(탈락 72건 중 72건)이고, 모델은 N2 를 요청받아도 **N2·N1 급수를 한 번도 달지 않은 채**(0/78) 주제의 기초 어휘(N4·N5 급수 — 외부 사전도 같은 판정)를 내서 창 밖으로 떨어진다. 가설은 맞다 — 다만 «급수를 솔직히 달아서»가 아니라 «**고르는 단어 자체가 쉬워서**»다(모델 급수와 사전 급수가 어긋나지 않는다).

**불편한 사실 4개 (결정에 영향)**
1. **한 단계 위(N3)도 «10/10» 이 아니다.** 3세트 통과 10·9·8장(평균 90%, 목표 이상 1/3). task-076 QA 의 «N3 = 10/10» 은 n=1 이었다. 게다가 **단어 난이도는 거의 안 움직였다**: 사전 평균 급수 이동 −0.08(완전 이동이면 −1), 방향 일치 이동분 +1.1%p, 모델이 단 N3 급수 5%(대조 0%).
2. **한 단계 아래(N5)는 모델 자기 신고만 크게 움직인다**: 모델 급수 평균이 +0.71 이동했지만 사전 기준은 +0.30(완전 이동이면 +1), 방향 일치 이동분 +1.6%p. 대조 N4 세트의 단어가 이미 사전 N5 가 63.6% 라 **바닥 효과**가 있다. «자기 신고 말고 사전으로 재라» 는 결정이 맞았다는 숫자다.
3. **사전 매칭률 51.8%(101/195)로 낮다** — N2 조건은 44.9%. 구·문형(予定があります, 都合がつきます)은 사전에 표제어가 없어 못 잰다. N2 에서 통과 7장이 나온 세트(v4)도 7장 중 5장이 구·문형이라 사전으로 확인되는 것은 2장(当日 사전 N2·誘います 사전 N3)뿐이다 — **«통과했지만 N2 어휘인지»는 대부분 사전으로 확인할 수 없다**.
4. 표본이 작다(조건당 3~6세트, 사전 매칭 단어 21~35개). 아래 이동분(%p)은 방향 확인용이지 검정이 아니다.

**지시의 «방향 일치율 +15%p» 정의에 주의**: 방향 일치율은 0 에서 시작하지 않는다 — 대조 세트 단어에 같은 식을 적용하면 N3 기준 22.7%·N5 기준 63.6% 가 이미 «챌린지 쪽에 가까움» 이다. 그래서 위 이동분은 **대조 기준선을 뺀 값**으로 적었다. 개선 후 판정도 이 정의(대조 대비)로 해야 하고, N5 는 바닥 효과로 +15%p 가 사실상 불가능하니 한 단계 위(N3) 하나로만 보는 것을 권한다.

## 1. 방법

- 하네스: `buildTopicWordsRequest` → `llm.completeJson`(task `topicWords`, tier·timeout 덮어쓰지 않음 — fast·20s·interactive), 연결은 task049 의 `STUB_CONNECTION` 방식(DB 접촉 0·운영 서버 접촉 0). `[수준]` 과 검사 ⑤ 창을 **같은 값(챌린지 난이도)** 으로 넣는다 — `learning/vocab/topicSet.ts` `runTopicWords` 와 같은 방식(`build({topic:{...topic, level}})`·`assemble(r.data,{level})`).
- 조건 4개(`[수준]` 값만 다름): N2(+2)·N3(+1)·N5(−1)·대조 N4. variant(이번 초점)는 운영 첫날이 항상 0 이라 세트가 거의 같아지므로 세트마다 돌렸다 — N3·N5·대조 {0,2,4}, N2 {0..5}.
- 호출 순서: variant 라운드마다 4조건을 돌려 가며 + 라운드 끝에 N2 추가 세트(1·3·5), 직렬·간격 ≥1.5초. 실제 순서: N2-v0 N3-v0 N5-v0 CTRL-v0 N2-v1 N3-v2 N5-v2 CTRL-v2 N2-v2 N2-v3 N5-v4 CTRL-v4 N2-v4 N3-v4 N2-v5.
- 항목별 탈락 사유: `assembleTopicWords` 를 앞에서부터 prefix 로 다시 돌려 항목마다 통과/사유를 분리(조립이 앞→뒤 순차·결정적이라 정확). **반사실**: `jlpt` 를 전부 null 로 바꿔 다시 조립 = 검사 ⑤ 를 껐을 때의 통과 장수.
- 급수 사전: `prisma/seed-data/jlpt/n1~n5.json`(N1 3,034·N2 1,767·N3 1,649·N4 629·N5 676, 표기 7,647개 — 공식 급수표가 아니라 시드 목록)을 `surface` 로 대조. 매칭 3단계: ⓐ표기 그대로 ⓑ정중·과거형을 사전형으로 되돌린 후보(飲みます→飲む, おいしいです→おいしい) ⓒ가나로만 쓴 표기는 읽기 대조. 급수가 여러 개에 걸친 표기는 «애매» 로 방향 계산에서 뺀다(이번 195항목 중 0개).
- **라이브 호출 수 = 정확히 15회**(N2×6·N3×3·N5×3·대조×3). 논리 호출 15·CLI 시도 15(전부 `attempts=1`, 재시도 0)·실패 0·429/한도 0·시험 호출 0(하네스 점검은 `DRY=1`/`DUMP=1` — 호출 없음). 모델 haiku, 호출 8.6~10.7초(전부 12초 fail-fast 안), 프롬프트 2,817~2,830자.
- 검증: 하네스 eslint 0·tsc(미러 전체) 0. 하네스에 `PLAN=improve`(개선 후 25회: N2×10·N3×6·N5×6·대조×3) 계획을 넣어 DRY 로만 확인했다(호출 없음).

## 4. 한계

- variant 를 0~5 로 돌렸다 — 운영 첫날(variant 0)과 같지는 않다. N2-v0(운영 첫날과 같은 입력)은 4장이었다.
- 프롬프트 변형 호출을 하지 않아 «왜 쉬운 단어를 고르는가»의 원인은 가능성 수준이다.
- haiku 시간대 편향 완화로 조건을 교차했지만 세트 6개의 순서 효과는 통제하지 못했다.

## 5. 개선 후보 (호출 없이, 근거 숫자와 함께 — 선택·검증은 개선 단계 몫)

1. **`[수준]` 을 단어 고르는 기준으로 올리고 하한을 명시한다.** 지금 `[수준]` 은 `jlpt` 칸 규칙(239행)에만 나오고 선택 기준(231행)에는 수준이 없다. 근거: 창 밖 N4·N5 항목 81%(63/78)·N2 급수 0/78. 방향: «카드의 절반 이상은 jlpt 가 [수준]인 표현으로 고릅니다. [수준]보다 두 단계 이상 쉬운 기초어(예: 食べる·カフェ·公園 같은 N5·N4 기본 어휘)는 내지 않습니다» + 239행 예시를 «N5 → N5·N4» 한 줄에서 위쪽 수준 예(«N2 → N3·N2·N1») 추가. **위험**: 급수 부풀리기(N5·대조에서 ±0.24~0.35 끌림 확인) — 개선 후 판정은 통과 장수가 아니라 **사전 기준 이동(대조 대비)** 으로 해야 한다.
2. **수준별 «이 정도 난이도» 예시 단어(주제와 무관한 고정 목록 2~3개씩)를 한 줄 넣는다.** 근거: 모델은 급수 척도를 안다(사전과 ±1 일치 93%) — 모자란 것은 척도가 아니라 생성 쏠림이라 예시는 «가르치기»가 아니라 «당기기»다. +60~90자 정도(현재 프롬프트 2,820자, 지연 8.6~10.7초 — 12초 fail-fast 와 1.3초 거리라 길이 증가는 지연을 직접 재 보고 정한다). **위험**: 예시 단어를 그대로 베낄 수 있다 — 예시를 제외 목록에 넣거나 주제와 먼 단어로.
3. **두 단계 이상 위에서는 «문형 조각(구)» 대신 «단어» 쪽으로 방향을 준다.** 근거: N2 에서 통과 7장이 나온 세트(v4)의 통과 항목 5/7 이 구·문형이라 사전으로 검증 불가(§3), N2 조건 전체의 구(句)모양 지표 52.6%(대조 66.7%라 조건 간 차이는 없음). 방향: 해당 조건에서만 «~ませんか·~ですか 로 끝나는 문형·정형 문장은 내지 않고 단어 또는 짧은 어구만» 문구 추가(수준 차이 ≥2 일 때만 — 프롬프트는 값이 아니라 문구라 `[수준]` 외 입력 줄이 필요할 수 있어 **developer 와 입력 줄 사양 협의**가 필요하다). **위험**: 통과가 더 줄 수 있다(구가 통과를 만들던 세트 v4 가 사라짐) — 사전 측정이 가능해지는 이점과 맞바꿈.

**배제(숫자로 닫힘)**
- **요청 장수만 늘리기(13→20)**: N2 요청 13 → 통과 평균 2.5장(19%)이라 20 요청이어도 3.8장 — 합격선(8장) 불가.
- **검사 ⑤ 창 완화(최후수단)**: 63개 모두 통과하지만 그중 사전 매칭 29개의 82.8% 가 N5·N4 라 «난이도를 N2 로 골라도 쉬운 단어» 가 되어 난이도 선택이 무의미해진다. 사용자 결정(① 프롬프트 먼저)과 같은 방향의 결론이다.
