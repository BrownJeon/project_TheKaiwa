# task-066 — 질문 탭 챗봇창 화면 + 글자·마이크 질문 + 확인 절차 제거

## 사용자 요청 (원문, 2026-10-13)
> 물어보는 방식을 채팅방식과 마이크로 말하는 방식 두가지로 만들어줘. 그리고 화면의 구성은 챗봇창과 같은 심플한 화면이었으면 좋겠어. 물어볼때도 알림창을 띄워서 컨펌을 받는게 아니라 바로 물어보도록 해줘

## 사용자 추가 설명 (원문, 2026-10-13 — 위 요청의 「마이크」 범위를 확정)
> 추가적인 설명으로 마이크로 말하는건 한국어가 아닌 일본어 단어나 문장이 어떤뜻인지 바로 물어보려고할때 사용하고싶은거야. STT는 회화에서 사용하는 로직을 사용하면 돼

→ **Leader 정정**: 마이크 = **일본어만**(한국어·섞어 말하기 아님), 인식은 **회화의 실시간 STT 재사용**(앱 온디바이스 sherpa, 웹/폴백 gateway — 일본어 전용). 따라서 앞서 가정했던 **한국어·일본어 섞어 말하기, 서버 Whisper 받아쓰기 새 경로(#181 가칭), `language` 인자, 지연 4~8초 예산, D5 언어 선택은 전부 폐기**한다. 아래 본문에서 해당 줄은 취소선/정정으로 표시. S0 스파이크 기록([[task-066-dev-stt0-record]])은 **무관 결과로 참고만**(지연·품질 수치는 이 용도에 적용하지 않는다).

## 관련 과거 이력 요약 (Leader 큐레이션)
- [[task-064-ask-anything-3a]] — 어제(2026-10-12) 운영 배포(릴리스 `20261012-232359-59eb4f85`). 3a = **글자 질문만**, 구조는 `/ask` 홈(질문 입력 카드·예시 칩·지난 질문 목록) + 질문 방 `/ask/[chatId]`. **첫 질문 때 「보내는 범위 안내」 시트 1회**(D2 안내 A, 기기별 `localStorage kaiwa.ask.scopeNotice.v1`)가 현재 유일한 동의 장치이고, 방 ⋯ 메뉴에서 다시 볼 수 있다.
- 그때 사용자가 요청한 마이크 질문(「마이크를 통한 말로 연상되는 단어나 문장을 말하거나 상황을 설명하면 강사가 번역이나 설명」)은 데모 v2 의 **L 탭**으로 설계됐지만 **D13 A「글자 먼저 → 음성은 같은 task 2단계」**로 사용자가 미뤘다. 2단계 착수 조건(이력서 task-064 97행): ① 한국어 받아쓰기 품질 실측(대표 발화 N개의 문장 오류율 기준) ② 요청마다 언어를 넘기는 인자(새 `language`) 추가 ③ 받아쓰기 경로 계약(경로·오류 코드·한도). **이 task 가 그 2단계다.**
- 기술 사실(task-064 때 확인): 실시간 음성 인식(앱 온디바이스 sherpa·gateway)은 **일본어 전용**(ReazonSpeech) — 한국어 불가, 안드로이드 기본 STT/TTS 는 금지. 서버 Whisper(VoiceVault whisper-service 재사용 `src/modules/engine/adapters/stt/fasterWhisper.provider.ts`)는 다국어이지만 지금은 **분석 잡(SpeechJob 큐) 경로**라 짧은 발화를 즉시 받아쓰는 길이 없다. 화면 쪽 `capture.ts`(getUserMedia→AudioWorklet)·`pcm.ts`(16kHz PCM16 변환)는 이미 있다.
- 승인된 교훈(`/이슈기록 관련 음성 STT 화면 데모 동의`): 없음.

## Leader 해석 (사용자가 바꾸라면 바꾼다 — 데모에서 확인받는다)
1. **「챗봇창과 같은 심플한 화면」** = `/ask` 를 열면 곧바로 **대화창 + 입력 바**가 보이는 구조. 지금의 홈(맨 위 입력 카드·예시 칩·지난 질문 목록)을 없애거나 대화창 안으로 흡수한다. 회화/채팅 방의 헤더·메시지 목록·입력 바와 같은 결을 쓴다. (한 개의 이어지는 대화창인지, 매번 새 대화인지는 데모 열린 결정 D1.)
2. **「채팅방식과 마이크로 말하는 방식 두 가지」** = 입력 바에 글자 입력 + **마이크 버튼**. ~~마이크로 한국어·일본어(섞어서)를 말하면 서버가 받아써서 질문으로 보낸다~~ → **(정정, 사용자 추가 설명)** 마이크로 **일본어 단어·문장**을 말하면 **회화와 같은 실시간 STT**(앱 온디바이스 · 웹/폴백 gateway)가 글자로 바꾸고, 그 글이 질문으로 가서 선생님이 **뜻·읽기·뉘앙스·예문**으로 설명한다(예: 「大丈夫」 → 뜻 설명). 3a 에서 이미 만든 질문 파이프라인(분류→본인 기록 조회→`ask@v1`→살균)은 그대로 쓰고 **입력만 늘린다.** 새 서버 경로 없음.
3. **「알림창 컨펌 없이 바로」** = 첫 질문 때 뜨는 「보내는 범위」 모달 시트와 그 확인 저장(`scopeNotice`)을 없애고 바로 보낸다.
