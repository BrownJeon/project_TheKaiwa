# task-067 — 지난 질문도 챗봇창 UI 로 · 질문 제목 지정 · 지난 질문 5개씩 페이징

## 사용자 요청 (원문, 2026-10-13 — task-066 배포 후 폰으로 써 보고, 지난 질문 화면 스크린숏 첨부)
> 지난 질문을 선택해도 기존 챗봇과 동일한 ui로 구성하게 해줘. 뒤로가기 버튼이 있는게 아니 기본 챗봇의 형태로 유지되면서 지난 이력만 이동하면 좋을것같아.
> 그리고 질문에 대해서 제목을 지정할수있도록하고 지난 질문이 많을경우 페이징처리해줘. 페이징의 기준은 5개야

- 첨부 스크린숏(사용자 폰, 다크): 「지난 질문」으로 연 대화가 **머리에 ‹ 뒤로가기 + 대화 제목(「〜ている 와 〜てある 차이가 뭐예요?」) + 「질문 · 선생님」 + ⋯** 가 있고 **하단 탭이 없는** 별도 화면 — 이것이 task-066 구현 가이드 §26-3 A 의 `/ask/<id>`(지난 대화 화면, 하단 탭 숨김)다. 사용자는 이 화면이 아니라 **탭 화면(머리 「질문」·「지난 질문」 알약·「＋ 새 질문」·⋯·아바타, 하단 탭 유지)에서 내용만 바뀌기**를 원한다.

## 관련 과거 이력 요약 (Leader 큐레이션)
- [[task-066-ask-chatbot-voice]] — 어제 오후 운영 배포(릴리스 `20261013-114952-fe50f143`). D1=B(열 때마다 빈 대화), 지난 질문은 머리 「지난 질문」 알약 → **시트(바텀시트) → `/ask/<id>` 지난 대화 화면**(designer 판단 J: 하단 탭 숨김 — **사용자가 이번에 반대**). 근거 카드 「질문으로」·새로고침 복원은 이미 `/ask?chat=<id>`(탭 변형)로 간다 — 이 경로가 사용자가 원하는 모양이다.

## Leader 해석 (사용자가 바꾸라면 바꾼다 — 데모에서 확인받는다)
1. **지난 질문 열기** = 시트에서 항목을 고르면 **같은 탭 화면(`/ask?chat=<id>`)에서 대화 내용만 바뀐다.** 머리(「질문」·「지난 질문」 알약·「＋ 새 질문」·⋯·아바타)·하단 탭·입력 바 그대로, **‹ 뒤로가기 머리를 쓰는 별도 화면은 없앤다.** 옛 `/ask/<id>` 주소는 `/ask?chat=<id>` 로 보낸다(북마크·옛 링크 대비).
2. **제목 지정** = 질문(대화)마다 제목을 사용자가 정할 수 있게. 지금도 ⋯ → 제목 바꾸기가 있으나 **눈에 안 띈다** — 접근 위치를 더하는 것으로 해석(데모 결정 D2). 만약 「첫 질문을 보낼 때부터 제목을 입력」을 뜻한다면 입력 바 단순함과 충돌하므로 데모에서 비교로 보여 드린다.
3. **페이징** = 지난 질문 시트에서 **한 쪽 5개**씩, 쪽을 넘기는 조작(이전/다음 또는 번호). 「더 보기」식 무한 목록은 대체한다.

## 열린 결정 (데모에서 ★ 권고안과 함께 묻는다 — designer 가 화면으로 보여 준다)
- D1 열기 방식·머리: ★ 같은 탭 화면 + 머리 제목은 「질문」 유지(현재 대화 제목은 어디에? designer 제안 — 메시지 목록 맨 위·⋯ 메뉴 윗줄 등) / 머리 제목을 대화 제목으로 바꿈.
- D2 제목 지정 위치: ★ A **머리/대화 윗부분의 제목을 눌러 바로 바꾸기** + 지난 질문 목록 각 행에서도 바꾸기 + ⋯ 메뉴 「제목 바꾸기」 유지 / B 첫 질문 보낼 때 제목 입력칸(선택) / C ⋯ 메뉴만(현행). 제목 규칙(최대 길이·빈 값 처리·「처음 질문으로 되돌리기」)은 designer 제안.
- D3 페이징 모양: ★ A `‹ 이전 · 1/3 · 다음 ›`(총 개수 필요 — 서버 additive `total`) / B 이전·다음만(총 개수 없이) / C 번호 1 2 3. 시트 안 높이·현재 대화 표시·진행 중/새 답 표시·삭제 유지·빈 상태.
- D4 지난 질문을 열 때 휴대폰 뒤로가기: ★ 기록을 늘리지 않는다(`replace`) — 뒤로가기는 이전 화면(다른 탭)으로. 사용자가 말한 「뒤로가기 버튼이 있는 게 아니라」의 뜻.
- D5 옛 `/ask/<id>`: ★ 서버 리다이렉트로 `/ask?chat=<id>`.

## 승인된 결정 (2026-10-13 16:19 사용자 「task-067 데모 v1 승인, 결정(D1~D6)은 권고대로」 — designer 기록의 ★ 전부)
- **D1** 지금 대화 제목은 머리 「질문」 **아래 작은 줄**(공용 `AppBar` 에 선택 prop 하나 — 다른 탭 불변). 머리 제목은 「질문」 유지.
- **D2 A** 제목 지정 = 머리의 제목 줄 누르기(제목 바꾸기 시트) + 시트 행 ⋯ + ⋯ 메뉴 「제목 바꾸기」 유지. 빈 값 = 저장 불가 안내(현행 「제목을 적어 주세요」). 1~100 코드포인트(계약 #30 불변).
- **D3 A** 지난 질문 시트 = 한 쪽 5개, `‹ 이전 · 1 / 3 · 다음 ›`, 마지막 쪽도 5칸 높이 유지. 서버 #27 응답에 `total` additive.
- **D4 A** 지난 질문 열기·「새 질문 시작」 모두 **history 를 늘리지 않는다**(`replace`) — task-066 §26-3 B 의 push 한 줄을 바꾼다. 뒤로가기 = 이전 화면(다른 탭).
- **D5 A** 옛 `/ask/<id>` → 서버 리다이렉트 `/ask?chat=<id>`.
- **D6** 시트 행 ⋯ 에 「제목 바꾸기」와 함께 「삭제」(확인 단계 유지) — 지금 시트에는 삭제가 없다는 사실을 알고 올린 신규 기능.
- 구현 때 지킬 점(designer 기록·task-066 교훈): 알약(진행 중/새 답) 값은 시트 쪽과 별개로 **최근 20개**를 계속 읽는다 · 행 높이는 최소 높이(글자 크게 보기에서 늘어남) · 주소 갱신은 `replaceAskUrl(null)` 한 곳(Next 16.3.2 `history.state` 금지 — F1) · 머리 제목은 `h1` 안 단추(제목 구조 유지) · 시트는 공용 Sheet 규칙(Esc·초점).
