## 설계에서 먼저 정할 것 (Leader 가 설계서에서 옵션 비교 + 권고안을 제시, 사용자 결정은 데모 검토 때)

- (b) **주제 기반 오늘의 단어**: `TopicChunk`→`WordEntry` 로 파생 vs 새 LLM 프롬프트 생성(A10 은 보강만) — 비용·품질·"정답 미노출·서버 채점" 원칙과의 호환.
- (c) **매일 생성 시점·중복 방지·재생성**: 자동(크론/첫 진입 시 lazy) vs 사용자 시작 — `claimLesson` 재사용 규칙, 사용자당 동시 생성 1개, 5초·3분 예산.
- (d) **010d 와의 병합 범위**: 챌린지가 소비하는 시나리오 카드(장소·상황)·`steps[]`·답장 연습 3모드 중 이번 챌린지 범위(1단계)와 후속 분리.
- (e) **수행 현황 지표**: "얼마나 잘 수행"의 정의(일일 목표 달성 여부·연속 일수(출석 아닌 수행 기준)·주제별 진행률·평가 점수 추이) — `StatsSnapshot(DAILY)`·`StudyLog.result`·`Attendance` 중 원천, 새 집계 필요 여부.
- (f) **계획표 개편 IA**: 달력 유지+챌린지 현황 카드 / 탭 안 서브탭 / "분석·성장 기록(#78)" 자리 통합 — 하단 탭 5개(회화·오늘·계획표·단어장·질문) 유지.

### 3. 점수·달성 정의

- "문제 n/5" 통일 일치 [확인]: §1-3(줄 74-82)·§6-1(459)·§9 JSON(`quizCorrect/quizTotal`)·§13-1. A4 `quiz` 정확히 5문항(`schemas.ts:497` `minItems/maxItems 5`)·점수 = round(정답/5×100) → {0,20,…,100}. "90점·평균 85" 는 줄 81·459 에 **금지 문구로만** 남고 본문 예시에는 없다. 스크립트로 평균 85 조합(수업 2·3개) = 0건 재확인.
- 80% 규칙: 한 카드 = `VocabAttempt` 1행·답은 1회(`answer:null` 조건 갱신 — `sessions.ts:430`), 세트 합 = `cardCount`. `ceil(0.8×n)` 부동소수 오차를 n=1..30 전수 점검 — 정수식 `ceil(4n/5)` 와 **모두 일치**(5→4·10→8·15→12·6→5·4→4·1→1). 4장 세트는 4장 전부가 필요(= 100%)함을 구현 때 안내 문구에 한 줄 권장(지적 번호 없음 — 참고).
- **빈틈**: `dailyGoal.wordCount` 미사용(M-2). 소급("만들기 전 오늘 공부도 센다")·`dailyGoal` 얼림은 스냅샷 기반과 **모순 없다** — 소급은 기간 안 스냅샷이 자동으로 덮고, 얼린 값은 `wordsMinRatio`·`ruleVersion` 뿐이라 판정식에 그대로 들어간다.
