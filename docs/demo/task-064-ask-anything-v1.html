하단 탭 「질문」(지금은 「준비 중」 자리표시)을 실제 화면으로 바꾼다. 일본어 표현·문법 질문과 내 공부 기록 질문(진도·복습·교정·배운 표현)에 선생님이 답하고, 기록을 근거로 한 답에는 근거 카드가 붙어 누르면 원래 기록으로 간다. 선생님이 낸 제안(단어·주제·기록·레벨)은 채택해야만 저장된다.

  2. →
  3. 2(처음 한 번) 보내는 범위 안내
  4. →
  5. 3질문 방 — 기다림 → 답
  6. →
  7. 4근거 열기 · 제안 고르기 · 이어 묻기
  • 경로 2개 /ask(목록·새 질문) · /ask/[chatId](질문 방, 하단 탭 숨김)
  • 새 API 없음 — 계약 #27·#28·#29·#30·#31·#32(ASK)·#38·#39 재사용. 답 형태 answerMd·sources·confidence·needsScope·proposals
  • 일본어 예문은 앱 공통 표시 스위치(히라가나·한글)를 따른다. 엔진·모델 이름은 어디에도 없다
  • 음성 입력·선생님 음성(ASK 는 소리 없음) · 교정 카드(ASK 는 교정하지 않음) · 의미 검색(3c) · 서버 쓰기 경로 변경

보는 방법

  • 위 「폭」으로 360·390·412 또는 3폭, 「화면」으로 밝게·어둡게.
  • 상태 탭(A~K) → 그 안의 작은 버튼으로 세부 상태. 휴대폰 안의 예시 칩·[물어보기]·근거 카드·[더 보기]·되묻기 칩·제안 버튼·⋯ 메뉴·표시 바는 실제로 눌린다.
  • 흐름 체험: B 「첫 방문」 → 예시 칩 → [물어보기] → 보내는 범위 안내 → 대기 → 답.
  • 휴대폰 높이 780px = 주소창이 보이는 S25+ 첫 화면. 질문·답·기록은 모두 합성 예시다.
먼저 알아야 할 것 3가지
  1. [확실] 턴 응답에는 답 글자가 조금씩 오는 이벤트가 없다(#32 SSE = accepted → status → done). 답은 끝에 한 번에 보이고, 기다리는 동안 보일 수 있는 건 단계(PROMPT·LLM·PARSE)뿐이다 — 최대 120초라 대기 화면이 중요하다(D6).
  2. [확실] 근거(sources[])에는 유형·날짜·라벨만 온다. 카드에 발췌 본문을 보일 수 없고, 이동 주소는 유형별로 화면이 정한다(아래 계약 메모).
  3. [확실] 「기록을 못 찾았어요」 표시와 되묻기 선택지는 지금 계약에 신호가 없다 — 데모는 그렸지만 구현하려면 Leader 의 계약 보완이 필요하다(계약 메모 ②③).

계약 메모 — Leader 확인 필요

  1. ① 근거 유형·이동 주소: sources[].type 값 목록이 계약에 없다. 데모 가정 — CORRECTION→/drawer/corrections?focus={id} · LESSON→/study/today/talk/{id} · SCENARIO→/study/ai/scenario/{id} · EVALUATION→/study/today/eval/{id} · STUDY_LOG→/plan?day={date}&log={id} · REVIEW(복습 항목)→ 전용 상세가 없어 /study/today(복습 카드) — 이 마지막 하나는 정해야 한다. 교정 모음의 focus 가 첫 쪽 밖 교정도 찾는지 확인 필요. 지운 기록이면 대상 화면의 「찾을 수 없어요」가 뜬다(소유자 검사 그대로).
  2. ② 「기록을 못 찾았어요」 신호: 화면이 「기록 질문인데 0건」을 알 방법이 없다. 제안 — conversation.records: "FOUND"|"NONE"|"SKIPPED"(additive) 또는 프롬프트가 답 첫 줄에 그 문장을 쓰게 한다(그러면 데모의 별도 줄 모양은 못 쓴다).
  3. ③ 되묻기 칩의 답 전달: 칩을 누르면 「지난 30일」 같은 글자 턴이 간다. 서버 의도 분류가 이 짧은 말만 보면 기록 질문인지 모른다 — 직전 USER 질문과 합쳐 분류하거나 #32 에 scope 를 더해야 한다. D5 C(선생님이 고른 선택지)는 needsScope 를 {question, options[]} 로 넓혀야 한다.
  4. ④ 목록 둘째 줄: ASK 방의 Chat.preview 를 무엇으로 채울지(D8). 권고 = 마지막 답 첫 줄(마크다운 기호 뺀 평문 ≤60자).
  5. ⑤ 제목: #28 title 에 첫 질문 앞 30자(코드포인트)를 화면이 넣는다 — 서버 변경 없음.
  6. ⑥ ADD_TOPIC 페이로드: 카드에 쓸 키(title·description?)가 계약에 없다 — prompt-engineer A9 계약에서 정한다.
  7. ⑦ 진짜 취소(D6 Y)는 턴 취소 계약이 없다. 지금은 화면을 떠나도 서버가 답을 계속 만든다(#32 끊김 = 오류 아님).
  8. ⑧ 안내 확인 기록: 서버 칸이 없어 기기별 localStorage kaiwa.ask.scopeNotice.v1 로 둔다(스키마 변경 없음 — 새 기기에서 한 번 더 보임). 범위가 바뀌면 키 버전을 올려 다시 보인다.
