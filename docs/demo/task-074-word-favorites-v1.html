결정 필요 — D1~D11 (★ = designer 권고, 기본으로 그림)

사용자 요청: 「단어장에 즐겨찾기 기능을 추가해줘. 단어목록에서 바로 등록할수있도록 해주고 조회필터에 즐겨찾기를 추가해줘. 또한 즐겨찾기 추가는 상세화면과 수정화면에서도 등록할 수 있도록 해줘」. 바뀌는 곳은 네 군데 — 목록 행의 별(지금 행은 통째로 버튼 하나라 별을 넣으려면 「열기 버튼 + 별 버튼」 형제로 쪼갠다) · 조회 필터의 즐겨찾기 · 상세 시트의 별 · 수정 화면의 별. 저장은 사용자별 단어 상태(보관과 같은 곳)에 칸 하나를 더하는 방식이라 DB 칸 추가 승인이 따로 필요하다(Leader 가 별도로 묻는다). 아래 라디오를 바꾸면 휴대폰 화면이 바뀐다. D11 은 Leader 사전안(L7)과 designer 의견이 다른 곳이다.

#결정★ 권고대안근거
D1조회 필터 — 자리·모양A 출처 줄(전체·내 단어·기본 단어) 오른쪽 끝에 별 모양 토글(보이는 44×32, 누르는 44×44). 켜면 채운 별 + 테두리, 머리 줄에 「· 즐겨찾기」B 정렬 줄 [보관함] 옆 「★ 즐겨찾기」 글자 토글 · C 조각 칩 줄 맨 앞 「★ 즐겨찾기」 칩 · D 출처 분절 4번째 칸 「즐겨찾기」자체 실측(22상태 × 3폭 × 글꼴 100·130%): A·C·D 는 잘린 글자 0. B 는 360px 에서 정렬 글자 세 칸이 모두 잘리고, 글꼴 130% 에선 세 폭 모두 잘리며 360px 정렬 칸 폭이 41px(44 미만). C 는 즐겨찾기(켜고 끄기)를 조각 고르기(하나만 고르기) 줄에 섞고, 단어가 0개라 조각 줄이 숨는 계정에선 필터도 사라진다. D 는 즐겨찾기를 「출처」의 하나로 만들어 「내 단어 + 즐겨찾기」를 함께 못 고른다(L3 AND 와 어긋남). A 는 행의 별과 같은 모양이라 뜻이 이어지고, 출처 줄은 「어떤 단어를 볼까」라는 같은 질문이다.
D2보관함과의 관계A 서로 독립(보관해도 별은 그대로) · 즐겨찾기 필터는 지금 보기 안에서 AND — 보관함 + 즐겨찾기 = 보관한 즐겨찾기만 (Leader L4)B 보관하면 별을 자동으로 끔 · C 보관함과 즐겨찾기 필터를 함께 못 켬(하나를 켜면 다른 하나가 꺼짐)보관은 「오늘의 단어에서 빼기」, 즐겨찾기는 「골라 보기」라 목적이 다르다. 보관을 풀었을 때 별이 살아 있어야 자연스럽다. B 는 사용자가 모르게 표시를 지운다.
D3즐겨찾기만 보기에서 별을 끄면A 응답 뒤 같은 쪽을 다시 읽어 그 행이 빠진다(다음 단어가 올라와 7줄을 채움) · 머리 줄·쪽 수가 바로 맞음 · 토스트 「즐겨찾기에서 뺐어요」B 행을 제자리에 두고(별만 꺼짐) 다음에 목록을 읽을 때 빠짐 — 숫자·쪽 수는 그때까지 예전 값지금 단어장 원칙(추가·수정·보관·삭제 뒤 같은 쪽 다시 읽기 — 로컬로 행을 빼면 쪽 행 수·개수가 어긋남)과 같다. B 는 쪽 번호 방식이라 [다음]을 누르면 뺀 개수만큼 단어를 건너뛴다(아래 「쪽 수 변화」 표). 즐겨찾기 필터가 꺼진 보기에서는 어느 안이든 다시 읽지 않는다(행이 빠질 일이 없음).
D4수정 화면의 별 — 저장 방식·자리A 시트 머리(제목 줄) ✕ 왼쪽 별, 보기·수정에서 같은 자리 · 누르면 [저장]과 무관하게 바로 반영 (Leader L5)B 수정 폼 맨 위 「즐겨찾기」 줄 — [저장] 때 함께 반영, [취소] 하면 되돌아감기본 단어는 수정 화면이 없어 상세에서 바로 반영할 수밖에 없다 — A 면 기본·내 단어·보기·수정이 모두 한 방식. 별이 폼 밖(머리)에 있어 「폼과 따로 저장」이 모양으로도 보인다. B 는 같은 별이 상세에선 즉시, 수정에선 저장 때라 두 방식이 섞인다.
D5갱신 방식A 누르는 즉시 별 모양을 바꾸고(낙관적) 응답까지 그 단어의 별만 잠금(연타는 무시, 요청 1건) · 실패하면 원래대로 되돌리고 토스트B 서버 응답 뒤에 바꿈 — 응답까지 그 별을 흐리게(처리 중)별은 가볍고 되돌릴 수 있는 표시라 즉시 보이는 게 맞다. 화면 읽기는 눌린 상태 변화를 그 자리에서 읽는다. 보관·삭제·수정은 지금처럼 응답 뒤(무거운 변경). 잠금이라 「마지막 값 우선·요청 취소」 처리가 필요 없다.
D6분류 칩 숫자A 그대로(보관 기준만) — 즐겨찾기를 켜도 칩 숫자는 바뀌지 않음 (Leader L3)B 즐겨찾기를 켜면 칩 숫자도 즐겨찾기 기준(분류 목록 API 에 조건 추가)지금 계정은 내가 정한 분류가 없어 칩 줄 자체가 안 보인다(§28-2 C). 쓰임이 드물어 서버 변경을 미룬다. 머리 줄 숫자는 즐겨찾기 기준이라 실제 개수는 거기서 보인다.
D7단어 추가 시트의 별A 이번엔 없음 (사용자는 「상세·수정」만 말함, Leader L6)B 추가 폼 맨 위 「즐겨찾기에 넣기」 줄 — 저장 직후 별도 요청추가 직후 목록 맨 위(최근 추가)에 보이므로 거기서 별을 누르면 된다. B 는 저장 성공 뒤 즐겨찾기만 실패하는 반쪽 상태를 새로 만든다.
D8별 모양·색A 꺼짐 = 외곽선 별 ink2, 켜짐 = 채운 별 accent — 모양(채움/외곽선)과 색 두 가지로 구분B 켜짐 = 채운 금색(warn) · C 켜짐 = 채운 ink(무채색)비텍스트 대비 3:1 기준 — 켜진 별 accent 는 면 바탕 라이트 4.80·다크 5.22, 필터 켬 바탕(accent-soft) 위 4.08·4.72, 꺼진 별 ink2 5.44 이상(계산). 금색 warn 은 라이트 흰 바탕 2.95:1 로 미달 → 쓰려면 새 색(Leader 합의). C 는 켜짐이 눈에 덜 띈다.
D9행에서 별 자리A 행 오른쪽 끝 칸(폭 48, 행 높이 전체가 누르는 곳) — 뱃지·맞힘 숫자 오른쪽B 행 왼쪽 앞 칸일본어 표현이 늘 같은 왼쪽 선에서 시작해 훑어보기 쉽다(지금과 같음). 오른손 엄지에 가깝다. B 는 표현 시작선이 48px 밀린다.
D10성공 알림A 별 모양 변화로 충분 — 토스트는 즐겨찾기만 보기에서 행이 빠질 때만 「즐겨찾기에서 뺐어요」 · 실패는 늘 토스트B 누를 때마다 「즐겨찾기에 넣었어요」/「즐겨찾기에서 뺐어요」목록에서 여러 개를 연달아 누를 때 토스트가 계속 쌓인다. 화면 읽기는 눌린 상태로 이미 알린다. 행이 사라지는 경우만 이유를 알려 준다.
D11별의 접근 이름 L7 과 다름A 이름은 늘 「즐겨찾기」(행은 「食べる 즐겨찾기」) + aria-pressed — 상태는 「선택됨/선택 안 됨」으로 읽힘B 행동형 이름 「즐겨찾기에 넣기」/「즐겨찾기에서 빼기」, aria-pressed 없음(지금 [보관하기]/[보관 풀기] 단추와 같은 방식)L7 은 바뀌는 이름 + aria-pressed 를 함께 쓰자고 했는데, 그러면 「즐겨찾기에서 빼기, 선택됨」처럼 상태를 두 번·반대로 읽는다(토글은 이름을 바꾸지 않는 것이 표준 — WAI-ARIA 작성 지침). A·B 중 하나만. 필터의 [보관함] 토글이 이미 A 방식이다.

  • 필터 상태는 저장하지 않는다 — 출처·보관함처럼 다른 탭에 갔다 오면 꺼진다(task-068 D2 와 같음).
  • 머리 줄 — 앞말은 지금 그대로(「단어 n개」·「내 단어 n개」·「보관한 단어 n개」·「‘q’ 검색 결과 n개」), 걸린 조건 굵은 글자 맨 앞에 「즐겨찾기」를 붙인다(「단어 8개 · 즐겨찾기 · 1쪽」). D1 D 를 고르면 앞말이 「즐겨찾기 n개」.
  • 빈 화면 우선순위 — 즐겨찾기가 켜져 있으면 다른 빈 화면보다 먼저: 다른 조건이 없으면 「즐겨찾기한 단어가 없어요」, 있으면 「조건에 맞는 즐겨찾기가 없어요」 + 걸린 조건 한 줄 + [즐겨찾기 조건 풀기]. 이때 「‘q’ 추가하기」는 내지 않는다(추가해도 즐겨찾기가 아니라 안 보임).
  • 보관 라우트에는 분당 한도가 없다(코드 확인) — L2 「보관과 같은 기준」이면 한도 없음. 서버가 한도를 두기로 하면 쓸 429 문구만 표에 준비했다(지금 단어장 버튼 오류 함수는 429 를 일반 문구로 바꾸므로 전용 문구가 필요).

알려진 한계

  • 목록과 열린 시트의 같은 단어 — 시트에서 별을 바꾸면 목록의 그 행도 함께 바뀐다(같은 상태를 씀). 다른 기기에서 바꾼 별은 목록을 다시 읽을 때(화면 복귀·쪽 이동) 맞춰진다 — 자동 새로고침은 지금도 없다.
  • D3 A 의 손가락 아래 밀림 — 행이 빠지면 다음 행이 그 자리로 올라온다. 응답 뒤 다시 읽기까지 0.3~0.6초쯤 걸리고 그 사이 같은 별은 잠겨 있어 연타로 다음 행을 끌 위험은 작지만 0 은 아니다(폰 확인 항목).
  • 데모 모형 — 응답은 0.6초(느림 2.5초) 모형, 전체 단어 수 7,766 은 합성 숫자이고 실제 행은 샘플 20개뿐이다. 낭독 낱말은 예시다.

사용자에게 묻고 싶은 것 (Leader 가 전달)

  • Q1 (D3) 즐겨찾기만 보는 중 별을 끄면 그 단어가 바로 목록에서 빠져도 될까? ★ 바로 빠짐(쪽 수·숫자가 맞고 다음 쪽에서 건너뛰는 단어가 없음). 대안은 제자리에 남김.
  • Q2 (D1) 필터를 글자 없이 별 모양 단추 하나로 둬도 알아보기 괜찮을까? ★ 별 단추(어느 폭·글꼴에서도 다른 글자를 안 자름). 글자 「즐겨찾기」가 꼭 보여야 하면 B(360px 에서 정렬 글자가 잘림)나 C(조각 칩 줄 맨 앞).

  • Q4 (D7) 단어 추가 시트에는 이번에 별을 두지 않는다 — 추가 직후 목록 맨 위에서 누르면 된다. 추가 시트에도 꼭 필요하면 말해 달라.
