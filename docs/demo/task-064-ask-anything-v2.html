  1. 답 기다리는 화면에서 이탈 버튼을 뺐다(v1 의 이전 안). 버튼 대신 30초·90초가 지나면(상태 D 의 35초·95초) 글자 안내 한 줄만 둔다 — 「다른 화면으로 가도 답은 계속 만들어져요. 돌아오면 이 질문 방에서 볼 수 있어요」. 나가는 길은 상단 ‹·안드로이드 뒤로 → 질문 목록(여기서 하단 탭으로 다른 화면)뿐 — 질문 방은 채팅 방처럼 하단 탭을 숨긴다. 목록의 「답 만드는 중」 행과 돌아왔을 때 「새 답」 표시는 그대로(상태 D).
  2. 마이크로 말해서 묻기를 더했다 — 입력 바 왼쪽 🎤, 목록 입력 카드 [🎤 말로 묻기]. 한국어로 상황을 설명하거나 생각나는 단어·문장(일본어 포함)을 말하면 받아쓴 글이 입력창에 채워지고, 확인·고친 뒤 보낸다(권고). 새 상태 탭 L 「음성 질문」.
  3. 결정 D6 정리(취소 버튼 없음) + 새 결정 D10~D13(음성 언어·보내기 방식·답 소리·구현 단계). 결정 패널 맨 아래 「내 선택 요약」 글을 승인 답장에 붙여 주세요 — 데모에서 고른 값은 저절로 전달되지 않아요.
  4. 앱 메뉴 이름 변경(task-065 배포분) 반영 — 하단 탭 「오늘」 → 「공부」(순서 회화·공부·계획표·단어장·질문, 아이콘도 지금 앱 그대로), 답 속 「‘공부’ 탭의 복습 카드」. 회화 홈 제목(「자유로운 대화」)은 이 데모에 나오지 않는다. 「오늘의 단어」 같은 기능 이름은 그대로.

무엇을 만드나

하단 탭 「질문」(지금은 「준비 중」 자리표시)을 실제 화면으로 바꾼다. 일본어 표현·문법 질문과 내 공부 기록 질문(진도·복습·교정·배운 표현)에 선생님이 답하고, 기록을 근거로 한 답에는 근거 카드가 붙어 누르면 원래 기록으로 간다. 선생님이 낸 제안(단어·주제·기록·레벨)은 채택해야만 저장된다.

  1. 1질문 탭에서 글로 쓰거나 🎤 말로 묻기
  2. →
  3. 2(처음 한 번) 보내는 범위 안내
  4. →
  5. 3질문 방 — 기다림 → 답
  6. →
  7. 4근거 열기 · 제안 고르기 · 이어 묻기
  • 경로 2개 /ask(목록·새 질문) · /ask/[chatId](질문 방, 하단 탭 숨김)
  • 새 API 없음 — 계약 #27·#28·#29·#30·#31·#32(ASK)·#38·#39 재사용. 답 형태 answerMd·sources·confidence·needsScope·proposals
  • 일본어 예문은 앱 공통 표시 스위치(히라가나·한글)를 따른다. 엔진·모델 이름은 어디에도 없다
  • (v2) 말로 묻기 = 받아쓰기: 말을 다 한 뒤 몇 초 동안 글로 바꾸고, 그 글을 입력창에 넣는다. 목소리는 이 앱 서버 안에서만 글로 바꾸고 저장하지 않는다 — 선생님에게는 글만 간다
  • 선생님 답을 소리로 읽어 주기(D12 — 권고는 이번엔 글자 답만) · 교정 카드(ASK 는 교정하지 않음) · 의미 검색(3c) · 서버 쓰기 경로 변경

보는 방법

  • 위 「폭」으로 360·390·412 또는 3폭, 「화면」으로 밝게·어둡게.
  • 상태 탭(A~L) → 그 안의 작은 버튼으로 세부 상태. 휴대폰 안의 예시 칩·[물어보기]·🎤·근거 카드·[더 보기]·되묻기 칩·제안 버튼·⋯ 메뉴·표시 바는 실제로 눌린다.
  • 흐름 체험: B 「첫 방문」 → 예시 칩 → [물어보기] → 보내는 범위 안내 → 대기 → 답.
  • 말로 묻기 체험: L 「대기」 → 입력 바 🎤 → (듣는 중, 언어 바꿔 보기) → [완료] → 글로 바꾸는 중 → 받아쓴 글 → [↑ 보내기] → 대기 → 답. 데모는 실제 마이크를 쓰지 않는다.
  • 휴대폰 높이 780px = 주소창이 보이는 S25+ 첫 화면. 질문·답·기록은 모두 합성 예시다.
먼저 알아야 할 것 4가지
  1. [확실] 턴 응답에는 답 글자가 조금씩 오는 이벤트가 없다(#32 SSE = accepted → status → done). 답은 끝에 한 번에 보이고, 기다리는 동안 보일 수 있는 건 단계(PROMPT·LLM·PARSE)뿐이다 — 최대 120초라 대기 화면이 중요하다(D6).
  2. [확실] 근거(sources[])에는 유형·날짜·라벨만 온다. 카드에 발췌 본문을 보일 수 없고, 이동 주소는 클라이언트 매핑 한 곳에서 만든다(Leader 결정 ①).
  3. [확실] 「기록을 못 찾았어요」(records.count)·되묻기 칩(needsScope.options + #32 scope)·목록 둘째 줄(preview)은 Leader 가 계약 보완으로 정했다(additive).
  4. [확실] 지금 실시간 음성 인식은 일본어 전용이다. 한국어로 말하려면 새 받아쓰기 경로가 필요하고, 말하는 동안에는 글자가 나오지 않는다(다 말한 뒤 몇 초). [추측] 한국어 받아쓰기 품질은 아직 재 보지 않았다 — 그래서 받아쓴 글을 확인·고친 뒤 보내는 것을 권한다(D10·D11·D13).

계약 메모 — v1 질문은 Leader 가 정함, v2 음성은 확인 필요

  1. ① 근거 유형·이동 주소(Leader 결정): LESSON | CORRECTION | SCENARIO | REVIEW | WORD | STUDY_LOG. 교정 → /drawer/corrections?focus=<id>(첫 쪽 밖도 찾는지 developer 확인) · 복습 → /study/today(공부 탭 복습 카드) · 나머지는 해당 상세. 주소는 클라이언트 매핑 한 곳(sourceHref). (v2 designer 확인 필요 2건) 평가 결과는 목록에 없지만 상세 화면(/study/today/eval/[id])이 있어 EVALUATION 추가를 제안(데모 H 탭 레벨 답이 씀) · 상황 연습(SCENARIO)은 지금 상세 화면이 없다(/study/ai/scenario/[id] 는 편집·변형만).

  4. ④ 목록 둘째 줄(Leader 결정): 목록 응답 preview = 마지막 답 첫 줄 평문 ≤60자(읽을 때 계산). 없으면 첫 질문.

  6. ⑥ ADD_TOPIC 페이로드: 카드 키(title·description)는 prompt-engineer A9 계약에서 정한다.
  7. ⑦ 기다리는 동안 떠나기(v2): 버튼 없음. 서버는 SSE 가 끊겨도 답을 끝까지 만들어 저장해야 한다 — ASK 턴에 req.signal 취소를 잇지 않는다(task-058 취소 신호는 #169·#178 한정).

  9. ⑨ 짧은 받아쓰기 경로(새로 필요): 녹음 파일(wav 16kHz 모노, ≤30초·≤1MB) + language: ko|ja(D10 B 면 auto) → {text, language, durationMs}. 동기 응답(목표 3~10초, 20초 넘으면 시간 초과). 원음을 저장하지 않고 추적·로그에 받아쓴 글도 남기지 않는다. 사용자당 동시 1건·분당 상한. 오류 코드 → 화면 문구(L 탭 권한·오류).
