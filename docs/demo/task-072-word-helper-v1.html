결정 필요 — D1~D9 (★ = 권고, 기본으로 그림)

사용자 요청 「업로드한 사진의 표시한 영역에서의 회화 메뉴의 방식과 같이 일본어 도우미를 추가해줘.」 → 회화방 입력 줄의 둥근 「가あ」 도우미(task-056, 승인 데모)를 단어 추가 시트의 표현 칸에 붙인다. 아래 표가 요약이고, 그 아래 선택지를 바꾸면 휴대폰 화면이 바로 바뀐다. D1′·D6′ 은 designer 가 더한 하위 결정, ★ 를 이력서 권고에서 바꾼 곳은 없다(D6′·D1′ 은 새로 정한 ★).

#결정★ 권고대안근거
D1버튼 위치·모양표현 라벨 줄 오른쪽 끝, 「말로 쓰기」 옆 둥근 「가あ」 44px(회화방과 같은 아이콘·같은 모양)입력 칸 아래 44px 줄 「가あ 모르는 말은 한국어로 찾기 ›」같은 기능은 같은 모양 — 회화방에서 이미 익힌 버튼. 360px 라벨 줄에 여유 약 190px(아래 「라벨 줄 세 폭」 실측). 줄을 더하면 키보드 위 공간이 44px 줄어든다.
D1′보이는 단계 designer 추가표현 1단계에만(뜻 채우기 전)폼 단계(직접 입력·초안 뒤)에도초안 뒤 표현을 바꾸면 이미 채운 읽기·뜻이 어긋난다. 폼(WordForm)은 수정 시트와 공용이라 건드릴 곳이 늘어난다. 「직접 입력하기」로 간 사람은 표현을 이미 안다.
D2판 형태시트 안 인라인 패널 — 표현 칸 아래, [뜻 채우기] 위로 펼침시트 위에 하위 시트시트 위 시트는 포커스 가두기·스크롤·닫기가 두 겹(공용 Sheet 의 Tab 누출은 기존 문제). 인라인은 결과가 표현 칸 바로 아래라 넣은 뒤 눈 이동이 짧다.
D3질의 입력한국어 글자만(한글 1자 이상·100자), placeholder 「예: 임팩트, 어색하다」— (한국어 음성은 범위 밖)인식기가 일본어 전용. 한글이 없으면 화면이 먼저 막고 「한국어로 써 주세요. 일본어는 위 표현 칸에 바로 적으면 돼요.」(서버 문구 비노출).
D4결과 카드일본어 20px(루비·한글 줄은 표시 설정) + 한국어 뜻 + ▶ + [표현 칸에 넣기] · 첫 카드만 + [다른 후보 n개 더 보기] · 「왜 자연스러운지」 줄 숨김후보 3개 모두 펼침 / 「왜」 줄 보임키보드 위 시트 본문은 360×780 에서 약 356px. 단어 하나에는 말투 설명이 필요 없다 — 뜻 줄과 꼬리표가 차이를 말한다.

이 상태

실측(이 화면)

직접 해 보기

  • 휴대폰 안 버튼은 눌러진다 — 「가あ」 → 칩 「임팩트」 → [표현 칸에 넣기] → [뜻 채우기].
  • 패널 입력칸에 직접 써도 된다: 「임팩트」「어색」「귀찮」 → 후보, 한글 없음 → 안내, 그 밖 → 못 찾음.
  • 찾는 중은 약 0.9초 뒤 「조금만 기다려 주세요」, 1.8초 뒤 결과(실제 5초·12초를 줄인 모형).

라벨 줄 세 폭 — 「표현」 · 「말로 쓰기」 · 「가あ」 한 줄

시트 본문 폭 = 화면 폭 − 32(좌우 16). 값은 이 브라우저 글꼴로 잰 실측이다. 「글꼴 130%」 줄은 휴대폰 글꼴 크기를 키운 경우(글자만 1.3배, 버튼 44px 고정).

알려진 한계 · 질문

  • [추측] 한 단어 질의의 모양 — 지금 프롬프트는 「하고 싶은 말」용이라 「임팩트」에 インパクト 대신 インパクトがあります 같은 문장이 1순위로 올 수 있다(L4 — 데모 승인 뒤 prompt-engineer 실호출 확인). 문장이 오면 그대로 표현 칸에 들어간다.
  • 한도·동시 1건 공유(L3) — 회화방 도우미와 합쳐 분당 10·하루 300·동시 1건. 단어 시트에서도 429·409 화면이 보일 수 있다.
  • 가타카나에는 루비가 없다 — 앱 규칙(루비는 한자 위에만). インパクト 의 읽기는 한글 줄([임빠꾸또])과 ▶ 로만 확인. 데모의 한글 줄은 앱 변환 규칙을 손으로 옮긴 값이고 실제는 읽기 분석 결과다.
  • 키보드가 올라오면 좁다 — 360×780·키보드 300 모형에서 시트 본문 약 356px. [물어보기]를 누르면 키보드가 내려가 결과가 보인다. 앱 WebView 의 키보드 높이 반영은 회화방 도우미와 같은 기존 한계(실기기 확인).
  • 공용 Sheet 의 Tab 누출(기존) — 이번엔 시트를 겹치지 않아 키우지 않지만 고치지도 않는다.
  • 파일 겹침 — task-073(문구 두 건)이 labels.ts·WordMicField.tsx 를 고친다. 이 작업은 WordMicField 라벨 줄에 끼울 자리가 필요해 순서 조정이 필요하다(가이드 §30-9).
  • 데모 모형 한계 — 「처음 안내」는 상태를 고를 때마다 다시 보인다(실제는 기기에 한 번). 초점 테두리는 그림이며, 「직접 해 보기」의 [넣기]만 실제 초점을 옮긴다.
