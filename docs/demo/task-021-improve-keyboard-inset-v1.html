키보드가 입력창을 가리는 문제 — 공통 수정 task-021데모 v1수준 deltaIMP-0008 · 바뀌는 곳: 키보드가 떠 있을 때의 화면 아래쪽만

제안: 키보드가 올라오면 화면 아래쪽이 키보드 위까지로 줄어든다 (모든 입력 화면 같은 규칙)

  1. R1키보드 높이는 앱 셸 한 곳에서 재고, 입력이 있는 모든 화면이 같은 값을 쓴다. 화면마다 따로 고치지 않는다.
  2. R2아래에 붙은 입력 바(채팅방·회화방 텍스트·수업 ⑤ 말하기)는 키보드 바로 위에 붙는다. 대화 목록은 맨 아래(최신 말풍선)를 유지한다. 입력 바 아래의 제스처 바 여백은 키보드가 있을 때 없앤다.
  3. R3하단 탭은 키보드가 열려 있는 동안 결정 D1(A 숨김 · B 키보드 위로 따라 올라감). 키보드가 닫히면 원래 자리.
  4. R4바텀시트는 통째로 키보드 위로 올라간다. 최대 높이는 지금처럼 남은 높이의 85%. 입력 중인 칸이 시트 안에서 가려지면 시트 안쪽만 스크롤해 칸 아래에 16px 이상 여유를 둔다. 확인 버튼 자리는 결정 D2.
  5. R5스크롤 화면 안의 입력(설정·수업 응용 답·메모·붙여넣기·초대코드)은 화면 스크롤의 끝이 키보드 위로 올라오고, 입력 중인 칸(여러 줄이면 커서가 있는 줄)이 키보드 위 16px 이상에 오도록 한 번 스크롤한다.
  6. R6위쪽 입력(단어장 검색)은 자리 그대로. 결과 목록의 끝만 키보드 위로 올라온다.
  7. R7토스트·안내 띠도 키보드 위에 뜬다. 키보드가 닫히면 모두 원래 자리, 보던 스크롤 위치는 유지. 두 손가락 확대는 키보드로 착각하지 않는다(지금 규칙 유지).

바뀌지 않는 것

  • 키보드가 없을 때의 화면 — 지금과 픽셀 단위로 같다(각 화면 첫 번째 틀).
  • 화면 구성·입력창 위치·버튼 순서·문구.
  • 음성 입력(푸시투토크) 경로와 🎤 ↔ ⌨ 전환 동작.
  • 웹 브라우저와 앱에서 같은 모습 — 키보드 높이를 어느 쪽에서 어떻게 재는지는 개발 원인 조사(범위 1)에서 정한다.

현재 열에 대해 — 사용자가 회화방 텍스트 모드에서 재현한 모습(키보드가 화면 위에 덮이고 화면은 줄지 않음)을 같은 원인으로 다른 화면에 그대로 적용해 그렸다. 웹 Chrome 에서는 일부 화면(채팅방)이 이미 제안처럼 줄어들 수 있고, 어느 환경에서 어디가 틀어지는지는 조사 결과로 확정한다.

키보드 높이는 실제 값이 아니라 데모용 임의 값(위 컨트롤에서 280·320·360px). 앱 설치 파일을 다시 받아야 하는 방식이 필요해지면 그때 따로 알린다.
