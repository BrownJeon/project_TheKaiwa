이 데모가 보여 주는 것

먼저 알릴 것 ① — Q9 예시의 스와이프 설명이 지금 동작과 다릅니다. Q9 예시는 「오른쪽 스와이프 = 알아요, 뜻 보기 후 왼쪽 = 몰라요」였지만, 지금 덱의 스와이프는 왼쪽 = 다음 카드(답한 뒤에만) · 오른쪽 = 이전 카드 · 위 = 다시 볼 카드 표시이고 알았어요/몰랐어요는 버튼으로만 고릅니다. 「스와이프는 기존과 똑같이」 지시를 따라 이 데모는 스와이프를 바꾸지 않았고, 스스로 표시는 뜻 보기 면의 버튼으로 합니다(결정 D0). 이렇게 해도 Q9 숫자(정답 2·오답 2·4문제 중 2개)는 같게 나옵니다(F 탭).
먼저 알릴 것 ② — 참고 화면이 아직 오지 않았습니다. 버튼은 설명만으로 만든 최소안입니다. 참고 화면을 받으면 v2 에서 버튼 구성을 다시 맞춥니다(D3·D7).
먼저 알릴 것 ③ — 화면만 바꿔서는 동작하지 않습니다. 지금 서버는 한 세트에서 객관식 답과 스스로 표시를 함께 받지 않고(모드가 다르면 거절), 4지선다 카드에는 답하기 전 뜻을 보내지 않습니다. 새 세트용 데이터·서버 변경은 developer·Leader 몫이고(아래 「Leader 확인」), 이 데모는 화면 흐름만 정합니다.

바뀌는 것

  • 오늘 카드·챌린지 단어 카드에서 「방식(4지선다/뒤집기 카드)」 줄이 사라지고 세트는 늘 카드로 시작
  • 카드 앞면을 누르면(또는 [객관식]) 같은 카드에서 4지선다가 열림 — 고르면 서버 채점
  • [뜻 보기] 면에 [단어 듣기]·[예문 듣기]
  • 한 세트 안에 객관식·스스로 표시가 섞이고, 결과는 합산(Q9)

바뀌지 않는 것

  • 스와이프 제스처·판정·동작(탭 10px · 위 80px · 좌우 60px, 왼쪽 = 다음 · 오른쪽 = 이전 · 위 = 표시)
  • 장수·분류 고르기, 세트 만들기·단어 고르는 규칙, 목소리·빠르기 설정
  • 결과 화면 구조(한 줄 추가만), 통계·연속 기록 계산

점선 테두리(이렇게) = 지금과 달라지는 곳. 위 「바뀐 곳 표시」로 끌 수 있어요. 휴대폰 아래 작은 글씨는 이 데모 안에서 잰 값(실기기 값 아님)입니다.

  • L1 데이터: 새 세트 카드는 보기와 뜻을 처음부터 함께 받아야 한다 — 지금 4지선다의 「답하기 전 뜻은 서버만 안다」(§5-0 3)가 화면 쪽에선 성립하지 않게 된다(채점 표시는 여전히 서버 응답으로만). 대안은 [뜻 보기]를 누를 때 뜻을 받는 요청 추가(지연·계약 추가).
  • L2 서버: #50 이 한 세트에서 보기 답과 스스로 표시를 모두 받아야 함(지금은 400). VocabSession.mode 저장 값·통계 분리 여부는 스키마 0 원칙 안에서.
  • L3 보기를 못 만든 세트: 지금은 뒤집기 세트로 강등 → 새 방식에선 「객관식 없는 카드 세트」(안내 문구만 바뀜).
  • L4 #53 다시 풀기는 지금 원 모드를 따름 → 새 방식으로 만들도록(D6 A).
  • L5 자리표시 상수 재측정, localStorage kaiwa.vocab.mode·MODE_OPTIONS 정리, keyAction 에 C 키 추가와 1~4 의미 분기 시험.
