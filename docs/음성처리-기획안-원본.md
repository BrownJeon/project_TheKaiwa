# 일본어 회화 앱 음성 처리 아키텍처 기획안

## 1. 목적

본 문서는 일본어 회화 교육 앱에서 사용할 STT(Speech-to-Text), TTS(Text-to-Speech), 음성 분석 구조를 정의한다.

단일 음성 엔진에 의존하지 않고 각 오픈소스의 강점을 역할별로 조합하여 다음 목표를 달성하는 것을 지향한다.

- 실시간 일본어 음성 인식
- 높은 일본어 인식 정확도
- 발화 종료 후 고정밀 재분석
- 자연스러운 일본어 TTS
- 향후 발음 평가 및 Pitch Accent 분석 확장
- 온디바이스/서버 하이브리드 구조
- 외부 상용 API로 쉽게 교체 가능한 Plugin Architecture

---

## 2. 적용 대상 오픈소스

본 프로젝트에서는 다음 4개 오픈소스를 기본 Speech Stack으로 활용한다.

| 오픈소스 | 주요 역할 | 적용 영역 |
|---|---|---|
| sherpa-onnx | 음성 런타임, VAD, Streaming STT 기반 | 모바일 및 실시간 음성 처리 |
| ReazonSpeech | 일본어 특화 음성 인식 모델 | 실시간 일본어 STT |
| faster-whisper | 고정밀 STT 재분석 | 서버 기반 검증/분석 |
| Style-Bert-VITS2 | 일본어 특화 TTS | AI 일본어 선생님 음성 |

각 오픈소스는 대체 관계가 아니라 역할을 분리하여 함께 사용한다.

---

# 3. 핵심 아키텍처 원칙

음성 처리 영역을 다음 세 가지 역할로 분리한다.

## 3.1 Realtime Engine

사용자가 일본어를 말하는 즉시 인식하는 영역이다.

주요 목적은 다음과 같다.

- 빠른 응답
- 자연스러운 대화 흐름 유지
- 모바일 환경에서 낮은 지연시간 확보

기본 조합:

```text
Microphone
    ↓
sherpa-onnx VAD
    ↓
sherpa-onnx Runtime
    ↓
ReazonSpeech Model
    ↓
Realtime Japanese Transcript
```

---

## 3.2 Analysis Engine

사용자 발화 종료 후 동일 음성을 다시 분석한다.

실시간 처리에서는 latency가 중요하지만, 교육용 분석에서는 정확도가 더 중요하기 때문에 별도의 고정밀 STT를 사용한다.

기본 엔진:

```text
faster-whisper
```

처리 구조:

```text
User Audio
    │
    ├── ReazonSpeech
    │       ↓
    │   Realtime Transcript
    │
    └── faster-whisper
            ↓
        Analysis Transcript
```

두 결과를 비교하여 최종 transcript 신뢰도를 높인다.

---

## 3.3 TTS Engine

LLM이 생성한 일본어 응답을 자연스러운 일본어 음성으로 변환한다.

기본 엔진:

```text
Style-Bert-VITS2
```

활용 예:

- 일본어 선생님 음성
- 친근한 캐릭터 음성
- Formal / Casual Style
- 학습자용 느린 발화
- 실제 회화 속도 발화
- 감정 표현 음성

# 5. sherpa-onnx 역할

sherpa-onnx는 전체 Speech Stack의 Audio Runtime 역할을 담당한다.

주요 역할:

- Voice Activity Detection
- Endpoint Detection
- Streaming Audio 처리
- Streaming STT
- 모바일 온디바이스 추론
- ONNX 기반 모델 실행

모바일 앱에서 음성을 서버로 계속 전송하는 구조를 최소화하고, 가능하면 온디바이스 처리를 우선한다.

예상 구조:

```text
Flutter / React Native
        ↓
Native Bridge
        ↓
sherpa-onnx
        ↓
ReazonSpeech
```

---

# 6. ReazonSpeech 역할

ReazonSpeech는 일본어 전문 STT 엔진으로 사용한다.

주요 목적:

- 일본어 회화 인식
- 짧은 발화 인식
- 조사 및 일본어 어휘 인식
- 일본어 일상 표현 인식

기본 역할:

```text
Realtime Japanese STT
```

실시간 회화에서 사용되는 1차 Transcript는 ReazonSpeech 결과를 사용한다.

예:

```text
Input Audio

「昨日、新宿で友達と映画を見に行きました」

↓

Realtime Transcript

昨日、新宿で友達と映画を見に行きました
```

---

# 7. faster-whisper 역할

faster-whisper는 실시간 회화용 엔진이 아니라 분석용 Secondary STT로 사용한다.

주요 목적:

- 발화 종료 후 고정밀 재분석
- ReazonSpeech 결과 검증
- 발음 분석용 Reference Transcript 생성
- STT 결과 차이 분석

예:

```text
ReazonSpeech

昨日新宿で友達と映画を見ました


faster-whisper

昨日、新宿で友達と映画を見に行きました
```

두 결과가 다를 경우 Speech Analyzer에서 추가 분석을 수행한다.

---

# 8. Transcript Ensemble

단일 STT 결과를 절대적인 정답으로 사용하지 않는다.

두 개 이상의 STT 결과를 비교하여 최종 Transcript Confidence를 생성한다.

예시 데이터 구조:

```json
{
  "realtimeTranscript": "昨日学校に行った",
  "analysisTranscript": "昨日学校に行って",
  "confidence": 0.61,
  "requiresReview": true
}
```

결과가 일치하는 경우:

```json
{
  "realtimeTranscript": "私は東京に住んでいます",
  "analysisTranscript": "私は東京に住んでいます",
  "confidence": 0.97,
  "requiresReview": false
}
```

---

# 9. Pronunciation Analyzer

STT는 사용자가 무엇을 말했는지 판단하는 시스템이지, 정확한 발음을 평가하는 시스템은 아니다.

따라서 별도의 Pronunciation Analyzer를 두어야 한다.

처리 구조:

```text
Audio
 │
 ├── STT
 │      ↓
 │    Transcript
 │
 └── Pronunciation Analyzer
        ↓
      Phoneme
        ↓
      Mora
        ↓
      Duration
        ↓
      Pitch Accent
```

향후 분석 대상:

- 長音
- 促音
- 撥音
- 清音 / 濁音
- Mora Timing
- Pitch Accent
- 발화 속도
- Pause
- Intonation

예:

```text
おばさん
おばあさん
```

또는

```text
きて
きって
```

같은 차이를 STT 결과만으로 판단해서는 안 된다.

```text

```

# 11. 학습용 TTS 모드

교육 앱에서는 일반 TTS와 학습용 TTS를 구분한다.

지원 모드:

## Native Mode

실제 일본인이 사용하는 자연스러운 속도와 억양.

```text

```

## Learning Mode

학습자가 따라 말하기 쉬운 속도.

```text

```

또한 동일 문장을 여러 번 비교해서 들을 수 있도록 한다.

```text
학습자용 발음
     ↓
자연스러운 발음
```

# 12. Plugin Architecture

Speech Engine을 특정 오픈소스에 강하게 결합하지 않는다.

모든 STT / TTS는 Interface 기반으로 추상화한다.

STT Interface 예:

```java
public interface SpeechToTextEngine {

    TranscriptionResult transcribe(
        AudioData audio
    );

}
```

구현체 예:

```text
ReazonSpeechEngine
WhisperEngine
OpenAIEngine
AzureEngine
GoogleEngine
```

TTS Interface:

```java
public interface TextToSpeechEngine {

    AudioData synthesize(
        String text,
        VoiceOptions options
    );

}
```

구현체:

```text
StyleBertVitsEngine
OpenAITtsEngine
AzureTtsEngine
ElevenLabsEngine
```

이를 통해 엔진 변경 시 애플리케이션 로직 변경을 최소화한다.

# 13. Configuration Driven Architecture

엔진 선택은 코드가 아닌 설정으로 관리한다.

예:

```yaml
speech:

  stt:

    realtime:
      engine: reazon

    validation:
      engine: whisper

  tts:

    engine: style-bert
```

향후 상용 API 적용 시:

```yaml
speech:

  stt:

    realtime:
      engine: reazon

    validation:
      engine: openai

  tts:

    engine: elevenlabs
```

형태로 교체할 수 있다.

# 14. Speech Engine Router

향후 단일 엔진 고정 방식이 아닌 상황별 Routing 구조를 도입한다.

예:

```text
Speech Request
      │
      ▼

Speech Engine Router

      │
      ├── Realtime
      │      ↓
      │   ReazonSpeech
      │
      ├── Analysis
      │      ↓
```

추후 다음과 같은 조건 기반 Routing이 가능하다.

```text

network state
language
latency
cost
confidence
user subscription
```

# 17. 비동기 분석 구조

실시간 대화와 정밀 분석을 분리한다.

Realtime Path:

```text
Audio
 ↓
ReazonSpeech
 ↓
Conversation LLM
 ↓
TTS
```

Async Analysis Path:

```text
Audio
 ↓
Queue
 ↓
faster-whisper
 ↓
Pronunciation Analyzer
 ↓
Learning Analysis
 ↓
Database
```

이 구조를 통해 Conversation Latency가 분석 작업의 영향을 받지 않도록 한다.

```text

→ Apache License 2.0

→ MIT

→ AGPL-3.0 관련 검토 필요
```

따라서 TTS는 교체 가능한 Plugin 형태로 설계한다.

# 23. 설계 원칙 요약

본 프로젝트에서는 다음 원칙을 따른다.

1. 단일 STT 엔진에 종속되지 않는다.
2. 실시간 처리와 분석 처리를 분리한다.
3. ReazonSpeech는 실시간 일본어 STT에 집중한다.
4. faster-whisper는 고정밀 검증용으로 사용한다.
5. sherpa-onnx는 Audio Runtime 역할을 한다.
6. TTS는 독립 서비스로 구성한다.
7. 모든 Speech Engine은 Plugin 형태로 추상화한다.
8. Speech Engine 선택은 Configuration으로 관리한다.
9. STT 결과와 발음 평가는 서로 다른 문제로 처리한다.
10. 장기적으로 Speech Ensemble 구조를 구축한다.
11. 서버 분석으로 인해 실시간 Conversation Latency가 증가하지 않도록 한다.
12. 상용 API를 언제든 대체 엔진으로 추가할 수 있도록 한다.

# 24. Claude Code 구현 시 권장 작업 순서

Claude Code에서는 다음 순서로 구현 계획을 수립한다.

```text
1. Speech Engine Interface 정의

2. ReazonSpeech Adapter 구현

3. faster-whisper Adapter 구현

4. TTS Adapter Interface 구현

5. Speech Engine Router 구현

6. Audio Session 모델 정의

7. Realtime / Async Pipeline 분리

8. Redis 또는 Queue 기반 Analysis Pipeline 구현
```
